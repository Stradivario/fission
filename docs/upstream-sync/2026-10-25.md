Fork commits on top of upstream is the layout to keep: `git log upstream/main..HEAD`
is exactly the fork's patch set, and the next sync is the same replay again.

```bash
git fetch upstream
git switch -c rebase/upstream-<date> upstream/main
git cherry-pick <fork commits, oldest first>   # resolve, go build ./..., continue
```

Build after **every** pick (`go build ./...`): two conflicts auto-merged into
broken or wrong code without any conflict marker (see below). After the replay,
`go vet ./...` and the full unit suite catch the test-only breakages that a build
does not.

## Behaviour changes that reach the Lambforge stack

- **Environment `terminationGracePeriod` defaults to 90s** (CRD default; was unset).
  All 26 production envs leave it unset and the fork computed **0s** from that, so
  every function pod was killed instantly on each roll. After the upgrade function
  pods get 90s and drain in-flight requests — but a terminating pod now holds its
  node resources for up to 90s during every roll (the `cx33` control-plane node is
  nearly full; Karpenter adds amd64 capacity). Set `terminationGracePeriod`
  explicitly on an Environment to choose otherwise.
  Upstream's release note says stored Environments keep their value until the
  next update — **not so**: CRD defaults also apply on read. On minikube an
  Environment created in January read `terminationGracePeriod: 90` right after the
  upgrade and its functions were rolled to a 90s grace + 90s preStop sleep. In
  production every function rolls onto the 90s drain at upgrade time.
- **CRDs are applied on every `helm upgrade`** by the pre-upgrade hook Job
  (server-side apply, `forceConflicts`), including 4 new CRDs (`functionversions`,
  `functionaliases`, `workflows`, `workflowruns`). The `fission-crd-guard`
  ValidatingAdmissionPolicy only matches that hook's ServiceAccount.
- **Stricter trigger schema:** `functionref.name` now has `maxLength: 63` on
  HTTP/time/MQ/kubewatch triggers (production: no trigger exceeds it). All other new
  CEL rules constrain only new optional fields.
- Hot-path service names are absolute FQDNs (`<svc>.<ns>.svc.cluster.local.`,
  `CLUSTER_DOMAIN`); CFKE's CoreDNS serves `cluster.local`.
- The executor rolls with `maxSurge: 0, maxUnavailable: 1` (no two executors at once).
- **Do not `helm upgrade --reuse-values` onto this chart.** The reused values lack
  the new top-level keys (`workflows`, …) and the render fails
  (`dig "enabled" … interface {} is nil`). Upgrade with the values file
  (`-f fission-autopilot-lowcost.yaml`), as production does.
- `fission env create/update --graceperiod` defaults to 90 (the old CLI's effective
  0 was a bug, #3684). Lambforge does not create environments through the CLI.

## Found on the way (affects production today)

Fixed on this branch (fork bugs, with production evidence):

- **Event hooks lost ~27% of deploy events.** `Dispatcher.Send` handed the async
  publisher the caller's context; the reconcile / cold-start request returned and
  cancelled it, and delivery died with `final retry failed, giving up … context
  canceled` (30 of 113 in 24h on 2026-10-25). Fixed with `context.WithoutCancel`;
  minikube after the fix: 14 delivered, 0 given up.
- **The same-namespace guard 403'd new pods.** Its unresolved-caller window was
  5×50ms; on a fresh node the kubelet reports a pod's IP much later, and production
  federation gateway pods had all 15 startup subgraph calls in 24h rejected as
  `caller namespace unresolved`. Now a ~3s backoff; minikube: a new pod calling
  instantly gets 200 (after ~1.6s), cross-namespace still 403.

Fork risks not changed (no production evidence yet):

- newdeploy's wait-for-build holds a function-reconcile worker (10 total) for up to
  600s (`NEWDEPLOY_BUILD_WAIT_TIMEOUT`) while a package builds; ten slow builds at
  once would stall every other function's reconcile, and the same wait sits on the
  router cold-start path.
- The event-hook publisher (upstream's `WebhookPublisher`) delivers serially with a
  60-minute per-attempt timeout behind a 32-slot queue; a hanging receiver stalls
  delivery and then blocks the build/deploy reconcilers calling `Send`.
- On a cache miss the guard lists pods cluster-wide (field selector) on every retry,
  with no negative cache: a steady stream of calls from an unknown IP costs ~7 API
  LISTs each.


- **`fission function test` is broken with the CLI Lambforge ships.** The old fork
  CLI calls `/fission-function/…` on the router's public listener, which moved to
  the internal listener (GHSA-3g33): `404 page not found`. Upstream's CLI (in this
  sync, #3588) uses the internal listener; with the loopback guard fix it works.
  Ship the new CLI in the graphql-server-lambdas image to fix it.
